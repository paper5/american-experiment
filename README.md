## π§  How it works

The whole app is one file (`index.html`): the design, the interactive logic, and the embedded SVG geometry for all 51 states (extracted from the original site's saved snapshot).

Every LLM call goes straight from your browser to the API provider using their browser-friendly endpoints:

- **Tickets** β one structured JSON call per ticket (`candidate`, `mate`, `platform`, `strengths`, `weaknesses`).
- **Simulation** β one structured JSON call per state. Each state gets a system prompt containing both tickets, the State of the Union, and its own demographics/political context, and returns `{"winner", "dem_share", "rep_share", "narrative"}`. The swarms run with a configurable concurrency limit, and every state is called independently β so a failure in one state never stops the night.
- **State chat** β a follow-up call per question, seeded with that state's narrative and vote.

An election is **51 requests** β roughly the per-request cost of your provider Γ 51. With parallel swarms at 5, a full simulation completes in about a minute on typical APIs.

## π Privacy & cost

- **Your key never touches a server you don't control.** It lives in `localStorage` and is sent only to the provider you chose.

## β οΈ Limitations

- The original promises swarms that "research live conditions on X". Without credentials that's not possible here, so agents deliberate from the model's knowledge of current conditions instead.
- Browser requests require the provider to allow CORS. Anthropic, OpenAI, and OpenRouter all do; self-hosted gateways may need a CORS-enabled frontend or proxy.
